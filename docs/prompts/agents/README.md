# The seven agents: prompt specifications

Each file in this folder is the complete specification for one DeepSeek agent: the static system prompt, the JSON reply contract, the Learner State slice it may see, the fallback, and the test fixtures its Zod schema must pass and fail. The Claude lane turns each file into `lib/agents/<name>.ts`; nothing in the prompts is improvised at implementation time.

Shared rules that apply to every agent and are implemented once in `lib/agents/shared.ts`:

1. **Prompt order** (for DeepSeek prefix caching): `[static system prompt] → [Learner State slice as JSON] → [tone + verbosity sentences] → [volatile payload]`. The system prompt never changes per request.
2. **JSON mode.** Every system prompt contains the literal word `json` and a schema example, because DeepSeek's JSON mode requires it. The route calls the Vercel AI SDK's `generateObject` (non-streaming agents) or `streamObject` (coach, diagnoser, buddy) with the agent's Zod schema; the DeepSeek provider maps that to JSON mode. If the installed provider version needs an explicit option to enable JSON mode, read `node_modules/@ai-sdk/deepseek` types before the first call and record the option in `docs/build-log.md`; never ship without JSON mode.
3. **Validation.** `generateObject` validates against the schema; on a thrown validation or empty-content error the route re-sends once with `"Your previous reply failed validation: <message>. Reply with valid json matching the schema."` appended as a user turn. On second failure the route returns `fallback(req)` and `fallback: true`, or `AgentError { error: 'upstream' }` (502) for modules without a fallback (Author). **Streaming agents never retry:** the route streams `{"partial": ...}` frames from `partialObjectStream` and ends with one `{"envelope": ...}` frame carrying the validated final object or `fallback(req)`; the client discards partials and commits only the envelope.
4. **Budgets.** `AGENT_TOKEN_BUDGETS` from the contracts. The route counts tokens with a `chars / 3.5` approximation (DeepSeek's tokenizer is close to that on English plus code), trims per the Learner State trim order, and if the prompt is still over `min(budget, AGENT_HARD_CEILING)` returns `AgentError { error: 'budget-exceeded' }` (413) instead of calling the model. Request bodies are Zod-validated per agent before anything else, with caps: `code` and `currentCode` 20,000 chars, `results` 20 entries, `messages` 6, `diffSinceLastHint` 8,000 chars.
5. **Tone sentences.** Generated by `toneSentence(profile)`:
   - playful → "Be playful and light; a joke is welcome if it is short."
   - supportive → "Be warm and encouraging; assume the student is trying hard."
   - tough-love → "Be blunt and demanding; no cushioning, no insults."
   - direct → "Be neutral and precise; no small talk."
   - verbosity short → "Keep every field to one or two sentences."
   - verbosity verbose → "You may use up to four sentences per field where it helps."
6. **Never mention** DeepSeek, Velocity, model names, or any institution in a reply. The agent speaks as "BroGram".
7. **No markdown fences inside JSON string fields** except where a field is explicitly markdown (Author's `prompt`).
8. **Model:** `deepseek-v4-flash`, `temperature 0.3` for Author, Planner, Reviewer; `0.6` for Diagnoser, Coach, Buddy, Profiler. `max_tokens` 4,000 for Author, 1,500 for everything else.
9. **Module shape.** Each module exports `name`, `system`, `schema`, `slice`, `payload`, `temperature`, `maxTokens`, and optionally `fallback` (absent for Author), `repair(req, reply): reply` (runs first; fixes, never fails; Coach and Buddy use it), and `routeCheck(req, reply): string | null` (runs second; a non-null message counts as a validation failure).
10. **Server-side hydration.** Before building any prompt the route loads from `exercises` with the service key whatever the agent needs that the client may not hold: `reference_solution` and full `tests` for Reviewer and Diagnoser (by `exercise.id`), and the example and parent rows for Author (by `exampleIds`, `parentExerciseId`). Client-supplied values for those fields are discarded.
11. **Rate limits.** Coach: one call per 60 s per user and 5 per exercise (counted from `attempts.hint_count` for that user and exercise, not memory). Buddy: 20 per hour. Author: 10 per hour. Every other agent: 60 per hour. The in-memory bucket is backstopped by a count over `agent_usage` for the last hour with the service key.
