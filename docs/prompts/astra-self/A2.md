## Installed API findings and adjustments
- Next 16.3.4 docs deprecate middleware.ts in favor of proxy.ts. Use the proxy export, keeping the shared middleware helper name.
- SSR 0.12.6 setAll receives cookies and cache headers; preserve both across redirects. getClaims data can be null. Browser client is created lazily with literal NEXT_PUBLIC env references.
- Server Components cannot mutate cookies. Banned layout branch delegates to /auth/signout, which verifies the ban again, clears cookies, and redirects to the shared one-line notice at /login?reason=banned. No-JS clients are signed out too.
- Restricted exercise checks also run in proxy because shared layouts are reused on navigation. Overwrite the internal pathname header instead of trusting incoming values.
- Scope Zustand stores to each SessionProvider to prevent cross-request/account leakage. Hydrate persisted LearnerState; use Claude's compiler only for a missing document, never overwrite persisted state with fabricated history or query integrity_events through a client role.
- Accept newer incoming LearnerState versions on server refresh while preserving newer in-memory revisions. A regression test covers both directions.
- Dashboard loads only public curriculum and exercise metadata; no agent call on mount. Buddy and wellness are usable contextual slots for A5a, with honest empty states.

1. Lost auth cookies/cache headers on redirects or attempted cookie mutation during layout rendering.
2. Restricted navigation bypass through reused layouts or treating profile/state query errors as permission to proceed.
3. Cross-user Zustand state or dashboard data becoming stale after learner/course changes.
