Use one common active/standby worker controller for Python, JS/TS, SQL and Mongo. Execute each test separately, load required packages on both workers before timing student execution, terminate on a maximum 5-second deadline, preserve completed results and mark remaining tests timeout. Abort must settle even during preparation. Report actual package names through a subscription API without changing RuntimeAdapter. Web uses isolated sandboxed iframes with source/nonce checks and fresh DOM per test. Java uses one Main.java submission with normalized Solution, the existing rate limiter, server guards and bounded Judge0 polling.

User rulings override the older plan: SQL gets a fresh fixture database per test; Mongo nonempty args are fixed checks, empty/sentinel args use parsed student JSON. Python stdin uses setStdin({ stdin }). No secrets or network are required for offline verification. Browser Pyodide loads the specified v314.0.6 CDN at runtime.

Verification: write meaningful tests first; run targeted `npm.cmd test -- <paths>`, then `npm.cmd test` and `npm.cmd run build`. Golden tests execute installed Pyodide under Node, TypeScript, sql.js, mingo, and web runner under jsdom; Java uses fetch stubs, including 401/413/503 and all status mappings. Automated worker tests verify deadline, termination, warm promotion and abort. The manual browser infinite-loop timing check is explicitly pending for Musa and will not be claimed.

Most likely failures:
1. Incorrect fixture/test conventions or function detection silently grade the wrong code; prove smoke and negative cases with actual engines.
2. Main-thread timers cannot stop synchronous student loops; execution must stay in terminable workers, with standby fully prepared and abort-safe message lifecycles.
3. Browser bundling accidentally pulls Node/WASM loaders or changes worker mode; inspect installed types and guides, build browser entries as well as route code, and record verification limits.

Integration decisions: infer Python function mode from JSON argument arrays and the last top-level definition (optional `# brogram:stdin` forces program mode); infer SQL schema preparation when all checks lack placeholders because RunRequest has neither fnName nor kind. Java route supports the required response plus failureKind for unambiguous status mapping. Mongo fixed checks parse no student code, preserving current shell-style seed references under the explicit user ruling. Free Mongo runs infer find/object, aggregate/pipeline, or update/plain-filter pair. Web sandbox deadlines use parent timer and iframe disposal as the plan specifies; synchronous iframe loops may share the browser event loop, so hard timing remains an explicit manual risk, not a measured claim.
